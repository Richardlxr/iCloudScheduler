# 输入框、附件读取与短期提醒验收

日期：2026-09-22。此记录覆盖输入窗交互、附件读取方式和只有时限措辞的待办如何变成提醒。

## 修复的三个问题

1. **提示文字与拼音重叠。** 提示文字原先按绑定的字符串是否为空显示，而输入法在上屏前的拼音只存在于 `NSTextView` 内部，不会写回绑定，于是提示一直压在正在输入的文字上。现在文本视图单独上报编辑状态（`setMarkedText`/`unmarkText`/`didChangeText`），提示同时依据绑定文本和这个状态。中途曾改为在文本视图内自绘提示，导致 `NSTextView` 退回 TextKit 1 兼容路径、回车不再插入换行，已放弃该做法并由原生检查固定住回车行为。
2. **拖入文件变成路径。** `NSTextView` 默认接受 `NSFilenamesPboardType` 与 `public.url`，把文件路径当文本插入。现在拖放和粘贴都先识别文件 URL 并交给附件流程，普通文字粘贴保持原样；拖动时输入卡片显示“松开以添加附件”。
3. **只有“尽快”的催办无法识别。** 群消息里的催办既没有日期也没有时刻，此前只能标记缺失并要求补全。现在模型只判断时限措辞的类别，具体时刻由本机换算。

## 时限换算

模型输出新增可选字段 `dueHint`，取值为 `asap`/`today`/`tonight`/`tomorrow`/`weekend`/`this_week`/`next_week`/`month_end`，只有在“待办 + 没有具体时刻 + 有时限措辞”时才允许出现；其余情况必须为 null，缺时刻仍然留空并写入 missing。契约仍然拒绝其他新增键。

换算全部在本机完成，以提交时刻和事件时区为准：

| 措辞 | 结果 |
| --- | --- |
| 尽快 / 今天 | 早于 08:00 时取当天 09:00；否则取一小时后向上取整到半点，越过当天 21:00（今天为 22:00）则改为次日 09:00 |
| 今晚 | 当天 20:00；已过则取一小时后的半点，深夜改为次日 09:00 |
| 明天 | 次日 09:00 |
| 周末 | 最近的周六 10:00；周六下午顺延到周日，周日按“尽快” |
| 本周内 | 本周五 09:00；周五至周日按“尽快” |
| 下周 | 下周一 09:00 |
| 月底 | 当月最后一天 09:00；不足 12 小时按“尽快” |

结果一律是不占忙碌时间的时间点提醒（`reminderMinutes=0`），并且必须晚于当前时间、能被写入日历前的同一个解析器接受；夏令时缺失时刻会逐小时后移。换算结果写入 `timingNote`，在确认窗口作为说明显示——它是产品默认规则，不是模型假设，因此不阻塞添加；`missing` 里与时间无关的条目（来源日期、矛盾、看不清）保持阻塞。

草稿仍缺时间时，卡片上提供“尽快 / 今晚 / 明天 / 本周内”四个按钮，使用同一套换算，不再调用模型。

## 附件读取

含文字层的 PDF（抽样页平均 20 字以上）默认提取所选页面的文字发送，不再转图，也不需要通过图片测试；扫描件按原路径转图并保留图片能力要求，可在附件卡片切换。所选页面没有可提取文字时报错，不发送空白内容。文本附件统一标注为 `【附件：名称】`，与提示词中的说明一致。

## 本机结果

- 108 项核心检查通过：时限换算的具体时刻、跨夏令时的全时段扫描、契约新字段与旧草稿解码、`missing` 的保留与清除。
- 33 项原生检查通过：输入法上屏前后的提示状态、拖入/粘贴文件转附件、普通文字仍按文字粘贴、文字层 PDF 与扫描件的读取路径。
- 84 项异步工作流检查通过：只有“尽快”的催办在后台模式下一次模型调用即添加、在确认模式下带说明进入确认、一键时限在本机补全并保持可添加、文本 PDF 不再要求图片能力而转图 PDF 仍然要求。

共 225 项离线检查。日志：`dist/validation/capture-timing-{core,native,workflow}.log`。没有付费模型请求、钥匙串读取或真实日历写入。

界面改动通过 `--review-fixture` 在本机窗口核对：空状态提示、输入后提示消失、附件卡片（缩略图、页码范围、按文本/按图片）以及缺时间草稿上的时限按钮。

## 边界

- 换算只发生在模型明确给出时限措辞、且没有具体时刻时。有具体时刻或全天范围一律以原文为准，`dueHint` 被丢弃。
- 无法识别的时限取值按没有时限处理，草稿继续要求补全，不会猜时间。
- 后台模式下换算出的提醒会直接添加。判断措辞类别仍由模型完成，误判会得到一个时间点提醒，可在近期记录里撤销。
- PDF 文字层判定按整份文档抽样，不逐页判断；文字层质量由来源决定，本机不做 OCR。
- 真实服务商对 `dueHint` 的遵循情况需要 `--model-contract-check` 联网核对，本次未执行。
